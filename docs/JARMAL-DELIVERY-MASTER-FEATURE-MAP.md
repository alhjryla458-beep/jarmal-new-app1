# جَرْمَل للتوصيل — خريطة الميزات الرئيسية v2

> هذه الخريطة تخص **جَرْمَل للتوصيل فقط**. تطبيق جَرْمَل لقطع غيار السيارات مشروع مستقل تمامًا ولن تُخلط ميزاته أو قاعدة بياناته مع هذا المشروع.

## 1) الحالة الحالية

### ✅ موجود ومُفعّل
- حسابات العميل / التاجر / المندوب + إدارة مستقلة.
- الطلبات ودورة حياتها: pending → accepted → preparing → ready_for_pickup → picked_up → on_the_way → delivered / cancelled.
- إنشاء طلب نقدي مع ضوابط COD.
- الدفع الإلكتروني وإيصالات الدفع ومراجعة الإدارة.
- محافظ التاجر والمندوب، السحب، الشحن، وقيود الحركات المالية.
- تسويات الكاش للمندوب.
- احتساب أجور المندوبين مع إعدادات إدارية قابلة للتهيئة.
- اعتماد المتاجر واعتماد المندوبين.
- مخزون المتاجر وحجوزات المخزون وحركات المخزون.
- أعضاء فريق المتجر وسجل التدقيق.
- دبوس موقع العميل + وصف الموقع.
- إلغاء آمن للطلب قبل مراحل التوصيل المتقدمة.
- المفضلة وإعادة الطلب.
- النقاط/الولاء والبنية الخاصة بالاسترداد.
- الخدمات/الباقات والدفع/الشحن ضمن البنية الحالية.
- لوحة إدارة منفصلة عن تطبيق العميل.
- إعدادات طرق الدفع وأجور المندوبين داخل الإدارة.
- مركز متابعة الطلبات وحالات التشغيل الأساسية.

### 🟡 موجود ويحتاج استكمالًا
- الإشعارات: توجد بنية/استخدامات داخل التطبيق لكنها تحتاج مركز إشعارات دائم وسجل قراءة.
- المحادثة: بنية chat_messages موجودة، وتحتاج تجربة مكتملة مرتبطة بالطلب ودعم الإدارة.
- البحث: يحتاج تحسينًا موحدًا حسب اسم المنتج/المتجر/الفئة والموقع.
- الخرائط: موجودة للموقع، وتحتاج تجربة حفظ الأماكن ومناطق التوصيل.
- المحافظ: البنية المالية قوية نسبيًا، وتحتاج واجهة تشغيل وتقارير أكثر عمقًا.
- الإدارة: تحتاج صلاحيات إدارية دقيقة، تقارير، CMS، Feature Flags وApp Studio.

### 🔴 مفقود ويستحق التنفيذ
1. رفيق جَرْمَل المتحرك والسياقي للعميل والتاجر والمندوب.
2. مركز إشعارات حقيقي: unread/read، تصنيف، deep links.
3. أماكن محفوظة: منزل، عمل، متجر، مخصص.
4. مستلم مختلف عن صاحب الحساب.
5. تعديل الطلب قبل بدء الشحن وفق سياسة آمنة.
6. مجموعات تنفيذ للطلبات متعددة المتاجر.
7. إعادة محاولة التوصيل عند فشل التسليم.
8. الإرجاع والاستبدال والاسترداد.
9. القسائم والعروض.
10. تذاكر الدعم وخدمة العملاء.
11. وضع الإنترنت الضعيف وحفظ المسودة محليًا.
12. ساعات العمل ومناطق التوصيل والتغطية حسب المنطقة.
13. ETA زمني مبسط للطلب.
14. سجل أحداث الطلب Timeline موحد.
15. إثبات التسليم عند الحاجة.
16. تقارير تشغيلية ومالية أعمق.
17. صلاحيات الإدارة التفصيلية.
18. JARMAL APP STUDIO لإدارة المحتوى والتصميم والميزات القابلة للتهيئة.
19. إعدادات تجربة المساعد/الشخصية المتحركة من الإدارة.
20. نظام حملات وعروض قابل للتشغيل/الإيقاف.

### 🔵 مرحلة مستقبلية
- ذكاء اصطناعي خارجي متقدم بعد نجاح المساعد المحلي/السياقي.
- تتبع GPS حي عندما تكون التكلفة والبنية مناسبة.
- تحسين المسارات متعدد التوقفات.
- تكاملات الشحن الخارجية.
- التوسع بين المحافظات.
- مزودون/موردون لخدمات ومنتجات عامة عند الحاجة.
- ميزات متقدمة للتجارة الإلكترونية الرقمية.

## 2) هوية المساعد — JARMAL COMPANION
- شخصية يمنية كرتونية أنيقة، ثوب أبيض ولمسات يمنية وخوذة توصيل.
- دخول وخروج سياقي من عناصر الواجهة بدل نافذة ثابتة فقط.
- حالات: idle، يفكر، يبحث، نجاح، خطأ، تحية، توصيل، احتفال.
- يعمل محليًا أولًا في الوظائف التي لا تحتاج نموذج AI مدفوعًا.
- يفهم القسم الحالي: بقالات، مطاعم، مقاهي، ملابس، صيدليات، متاجر وغيرها.
- للعميل: بحث، طلب، حالة الطلب، المساعدة، الأماكن، المنتجات.
- للمندوب: الطلبات، الأرباح، التسويات، التنبيهات، الدعم.
- للتاجر: الطلبات، المخزون، المبيعات، التنبيهات.
- للإدارة: إرشاد وتشغيل، دون إعطاء الشخصية صلاحيات مالية أو أمنية غير مباشرة.
- يجب أن تكون الحركة خفيفة وتدعم الأجهزة والإنترنت الضعيف.

## 3) ميزات اليمن التي نعتمدها
- عنوان: وصف حر + دبوس + معلم + هاتف؛ لا نعتمد رقم منزل إجباري.
- محافظ إلكترونية قابلة للتهيئة من الإدارة.
- COD محلي وفق المنطقة/الفرع وسياسة آمنة.
- المناطق: محافظة → مديرية → منطقة → نطاق توصيل.
- رسوم توصيل قابلة للتهيئة حسب المسافة/النطاق/حجم الطلب.
- دعم منخفض الاتصال.
- دعم/هاتف fallback عند تعطل الاتصال.
- متجر استلام Pickup.
- ملاحظات للمندوب.
- مستلم بديل.
- إعادة محاولة التوصيل.
- سياسات إرجاع واضحة قبل تفعيلها ماليًا.

## 4) ضوابط لا يجوز كسرها
- لا نخلط أي كود أو جداول خاصة بقطع السيارات في هذا المشروع.
- لا DROP/RESET لقاعدة الإنتاج.
- لا بيانات وهمية.
- لا تغيير RLS أو المال من محرر بصري.
- كل عملية مالية عبر RPC آمن.
- لا نسمح للمستخدم برفع صلاحية نفسه إلى admin.
- كل تعديل: Inspect → Understand → Modify → Verify.
- كل تطوير يتم على redesign-jarmal، ولا نلمس main.

## 6) فصل المشاريع — قاعدة ثابتة
**جَرْمَل للتوصيل:** احتياجات يومية + متاجر + توصيل + عميل + تاجر + مندوب + إدارة.

**جَرْمَل لقطع الغيار:** مشروع مستقل لاحقًا. لا نضيف إلى هذا التطبيق: part_number، vehicle_make، vehicle_model، توافق السيارات، كتالوج قطع الغيار، موردي قطع السيارات أو أي منطق خاص بها.
